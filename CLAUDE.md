## What This Is

Interactive knowledge graph explorer. Users type a seed concept, an LLM generates related concepts via BFS expansion, and a Deck.gl frontend renders the growing graph with d3-force physics.

## Commands

```bash
# Run server (serves frontend at http://localhost:8080)
python server.py

# Run all tests
pytest -v

# Run a single test file
pytest test_server.py -v
pytest test_generator.py -v

# Tests require: pip install pytest pytest-aiohttp aiohttp
# Integration tests (test_integration.py) require live API keys
```

## Architecture

Single-page app with no build step. Five files carry all the logic:

- **`db.py`** — `GraphDB` class: SQLite storage (WAL mode) with thread-safe read/write separation. Nodes have `(id, name, year, description)`, edges have `(source, target, weight)`. Provides BFS traversal and subgraph queries.
- **`generator.py`** — LLM integration. `expansion_loop()` runs async BFS: picks a node, calls an LLM to generate related concepts, parses the text response, and upserts into the DB. Supports 5 backends (OpenAI, Anthropic, Gemini, DeepSeek, Grok) via a unified `BACKENDS` dict. Also provides `describe_node()` and `name_clusters()`.
- **`server.py`** — aiohttp REST API. `create_app(db_path)` factory returns the app. SSE streaming via `/api/stream` pushes real-time graph updates to the frontend. Expansion runs as a background `asyncio.Task`.
- **`index.html`** — Complete frontend in one file. Deck.gl ScatterplotLayer + LineLayer for rendering, controls panel for physics tuning, prompt editing, and backend selection. Settings persist to localStorage.
- **`force-worker.js`** — Web Worker running d3-force simulation. Receives node/edge data via `postMessage`, ticks the simulation, and posts back updated positions.

## Key Patterns

- **LLM response parsing**: `_parse_text_concepts()` in generator.py handles messy LLM output — strips numbered lists, `<think>` tags, and extracts `(name, year, weight)` tuples via regex. When modifying, test against multiple LLM backends since output formats vary.
- **SSE broadcasting**: `broadcast()` in server.py fans out events to all connected clients via asyncio queues. Events: `new_node`, `new_edge`, `status`, `done`, `description`, `cluster_names`.
- **Node IDs**: Generated by `_make_id()` — lowercased, stripped name used as the SQLite primary key. This means node identity is name-based; duplicate concepts with different casing merge.
- **Test fixtures**: Server tests use `aiohttp_client` fixture with a temp DB (`tmp_path`). Generator tests mock the LLM calls.
- **Async test mode**: pytest.ini sets `asyncio_mode = auto` — all async test functions run automatically without `@pytest.mark.asyncio`.

## Environment Variables

At least one LLM API key must be set: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY`, `DEEPSEEK_API_KEY`, or `XAI_API_KEY`. Optional: `PORT` (default 8080), `KNOWLEDGE_DB` (default `knowledge.db`).
